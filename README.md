# FoodStorage — сервис контроля запасов продуктов

## Назначение и аудитория

Консольное приложение для людей и семей, которые хотят учитывать домашние
продукты, планировать покупки и следить за сроками годности.

## Предметная область и сущности

- **Продукт**: ID, название, единица измерения и минимальный желаемый запас.
- **Запас**: отдельная партия продукта с ID, ссылкой на продукт, количеством
  и сроком годности. У одного продукта может быть несколько партий.
- **Количество** и **срок годности** — свойства запаса.

В ПР3 данные представлены коллекциями объектов `Product` и `Stock`.
Количество каждой партии выражается в единице измерения её продукта.
Название продукта уникально без учёта регистра.

## Возможности приложения

1. Каталог продуктов с пригодным остатком и статусом достаточности запаса.
2. Добавление продуктов и партий с разными сроками годности.
3. Частичное списание количества и удаление партии целиком.
4. Поиск по части названия без учёта регистра, сортировка продуктов по названию.
5. Просмотр партий по сроку годности; фильтр просроченных и истекающих за 3 дня.
6. Список покупок до заданного минимального запаса.
7. Статистика: число продуктов, партий, просроченных партий и продуктов к покупке.
8. Загрузка JSON при запуске и сохранение после каждого изменения.

Поведение трёх функций ПР1 сохранено: `get_stock_status` и
`calculate_purchase_quantity` стали методами `Product`,
`get_expiry_status` — методом `Stock`.
Просроченные партии не входят в пригодный остаток. В учебной модели партия
со сроком годности сегодня ещё учитывается. Полностью списанная партия удаляется.
Списание возможно и для просроченной партии, например при утилизации.
Статистика не суммирует килограммы, литры и штуки между собой.

## Объектная модель ПР3

| Класс | Назначение и атрибуты | Основные методы |
| --- | --- | --- |
| `Product` | Продукт: `id`, `name`, `unit`, `minimum_quantity` | `__init__`, `__str__`, `get_stock_status`, `calculate_purchase_quantity`, `to_dict` |
| `Stock` | Партия: `id`, ссылка `product`, `quantity`, `expiry_date` типа `date` | `__init__`, `__str__`, `consume`, `is_expired`, `get_expiry_status`, `to_dict` |

Партия содержит сам объект продукта: `stock.product.name`, а не словарь или
отдельную копию названия. Несколько партий одного продукта ссылаются на один
экземпляр `Product` из каталога. При этом количество каждой партии независимо.
Внешний словарь `data` группирует две коллекции объектов; словари в списке
покупок представляют строки отчёта, а не хранимые сущности.

```python
from datetime import date
from products import Product
from stocks import Stock

milk = Product(1, "Молоко", "л", 5)
batch = Stock(1, milk, 2, date(2026, 9, 26))
batch.consume(0.5)
print(batch)  # Партия 1: Молоко — 1.5 л; годен до 26.09.2026
print(milk.calculate_purchase_quantity(batch.quantity))  # 3.5
```

**Инкапсуляция:** `_quantity` закрыта от обычного присваивания через свойство
`quantity`, списание выполняется через `consume` с проверкой допустимости.
Это соглашение Python и контролируемый публичный интерфейс, а не защита
от намеренного обращения к `_quantity`. `minimum_quantity` имеет проверяющий
сеттер `@property`. ID, название, единица измерения и связь партии доступны
для чтения. Конструкторы отклоняют некорректные значения.

**Полиморфизм:** `str()` и `print()` вызывают разные реализации `__str__`
для `Product` и `Stock`; эти представления применяются в меню.

**Наследование и связи:** оба класса неявно наследуют `object`, переопределяя
`__str__`. Продукт и партия не являются разновидностями друг друга, поэтому
наследование между ними не вводится. `Stock` содержит ссылку на `Product`;
продукт существует независимо от партии, то есть это агрегация объектов.
При появлении настоящих разновидностей с общим поведением можно обоснованно
добавить наследование. `@property` используется для управления доступом
к состоянию; отдельные декораторы без практической задачи не добавлялись.

Операции над коллекциями (`add_product`, `find_product`, `search_products`,
`add_stock`, `consume_stock`, `shopping_list`, сортировка и статистика)
остались функциями. `consume_stock` находит объект, вызывает `stock.consume`
и удаляет его из коллекции, когда остаток равен нулю. Ввод, чтение и запись
файлов также остаются функциями. `main.py` организует меню и вызывает их.

## Установка и запуск

Проверено на Python 3.13.7. Для самого приложения достаточно стандартной
библиотеки; pytest и flake8 нужны для проверки работы.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

Если `.venv` уже создано, повторное создание не нужно. Без активации:

```bash
.venv/bin/python main.py
```

В меню сначала выберите **2** (добавить продукт), затем **3** (добавить партию).
Количество можно вводить с точкой или запятой; дата вводится как `2026-09-26`.
Для выхода выберите **0**. При Ctrl+C или завершении ввода незавершённая операция
отменяется, а ранее завершённые изменения остаются сохранёнными.

По умолчанию используется `data/inventory.json` относительно папки проекта,
независимо от текущей папки терминала. При первом запуске каталог пуст;
файл создаётся после первого изменения. Личные рабочие данные исключены из Git.

Произвольный файл можно указать явно:

```bash
python main.py --data /tmp/foodstorage.json
```

Для знакомства с подготовленными данными используйте их копию:

```bash
cp data/example.json /tmp/foodstorage-demo.json
python main.py --data /tmp/foodstorage-demo.json
```

В примере даты зафиксированы: 23 и 26 сентября 2026 года, 24 сентября 2027 года.
Статусы зависят от текущей даты. На 24.09.2026 молока пригодно 2 л, нужно купить
3 л; один просроченный литр не учитывается. Риса достаточно.

## Хранение и обработка ошибок

Формат ПР2 сохранён: старые файлы читаются без миграции. При загрузке
`deserialize_data` сначала создаёт продукты, затем партии со ссылками
на созданные продукты. `serialize_data` вызывает `to_dict`, проверяет
целостность ссылок и сохраняет даты строками, а ссылки — идентификаторами.

Один JSON-файл содержит связанные коллекции `products` и `stocks`:

```json
{
  "products": [
    {"id": 1, "name": "Молоко", "unit": "л", "minimum_quantity": 5}
  ],
  "stocks": [
    {"id": 1, "product_id": 1, "quantity": 2, "expiry_date": "2026-09-26"}
  ]
}
```

ID — уникальное положительное целое внутри своей коллекции. Даты хранятся
строками `ГГГГ-ММ-ДД`, количество партии положительно, минимум неотрицателен.
Числа NaN и бесконечность отклоняются. Для дробного вычитания и суммирования
используется `Decimal`, чтобы обычные десятичные количества не оставляли
ложные остатки из-за двоичной арифметики float.

Некорректный ввод запрашивается повторно. Неизвестные ID и превышение количества
при списании выводят сообщение, не завершая приложение. При повреждённом файле
программа сообщает об ошибке и завершает запуск без перезаписи данных.

Сохранение выполняется через временный файл и замену прежнего файла целиком.
При ошибке записи прежние данные сохраняются; изменение не применяется в меню.
Приложение рассчитано на один одновременно работающий процесс с файлом данных.

## Проверки

Из корня проекта с активированным окружением:

```bash
pytest -v
flake8 .
```

Либо `.venv/bin/python -m pytest -v` и `.venv/bin/python -m flake8 .`.
Тесты используют временные файлы и не изменяют рабочие данные пользователя.
Проверяются расчёты, границы сроков, дробное списание, JSON, восстановление
после перезапуска и сохранность данных при ошибках записи.
Дополнительно проверены конструкторы и методы объектов, инкапсуляция,
`__str__`, общие ссылки на продукт, совместимость JSON ПР2 и копирование
объектов при откате неудачной операции. Всего проходят 56 проверок.

В VS Code выберите `.venv/bin/python` через `Python: Select Interpreter`,
затем конфигурацию «FoodStorage: отладка ПР3» на панели запуска. Порядок
демонстрации приведён в `DEBUGGING.md`.
